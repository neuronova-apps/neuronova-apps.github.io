Política de privacidad

Esta política describe el comportamiento real de la demo web: qué oraciones, notas de seguimiento, reflexiones y acciones devocionales se guardan en el navegador, cómo se validan y qué controles locales existen para gestionarlas.

Responsable

Mi Momento forma parte de Neuronova Apps, iniciativa personal e independiente desarrollada por Gabriel Berrospi.

02

Alcance actual

Esta política corresponde a la demo web funcional publicada en GitHub Pages. Actualmente permite guardar y gestionar oraciones personales, añadir notas de seguimiento, crear, editar y eliminar reflexiones del diario y registrar progreso devocional local generado por acciones realizadas en la propia demo.

La biblioteca continúa siendo limitada: cada plan muestra una duración conceptual mayor, pero la versión actual solo publica tres sesiones completables por plan. Las cuentas, sincronización, copias de seguridad y otras funciones siguen sin implementarse.

03

Datos y almacenamiento local

La demo puede utilizarse sin crear una cuenta y sin proporcionar nombre, correo electrónico, teléfono u otros datos identificativos.

Mi Momento utiliza localStorage con la clave mimomento-local-v1. El objeto guardado declara version: 1 y puede contener prayers, journal y devotional.

En una oración pueden conservarse ID local, título, texto, categoría, estado, fecha visible y marcas técnicas de creación, actualización y respuesta. También puede conservarse una colección de notas de seguimiento vinculadas a esa oración.

En una reflexión del diario pueden conservarse ID local, fecha visible, texto y marcas técnicas de creación y, cuando fue editada, de actualización. Estos datos se procesan en el navegador y no se envían a una base de datos propia de Mi Momento en la configuración actual.

04

Seguimiento de oraciones

Cada nota de seguimiento puede contener un ID local, un texto de hasta 600 caracteres y una marca temporal técnica. Las notas se guardan dentro de la oración a la que pertenecen y se muestran como historial.

Cuando una oración se marca como respondida, la aplicación conserva el contenido y las notas existentes y registra answeredAt. Editar título, categoría o texto no elimina el historial ni cambia el estado de la oración.

Una oración respondida puede continuar recibiendo notas. Los contadores de activas y respondidas se derivan del estado actual de las oraciones personales y no incluyen ejemplos precargados.

05

Progreso devocional

El bloque devotional guarda únicamente registros de acciones completadas. Para el devocional diario se conserva la fecha local de finalización y una marca temporal técnica. Para los planes se conserva la sesión completada —actualmente de 1 a 3—, su fecha local y una marca temporal técnica.

La racha, el porcentaje de avance, el total de sesiones y el calendario de los últimos 28 días no se guardan como cifras independientes. Se recalculan en el navegador a partir de los registros válidos.

El porcentaje global de planes usa únicamente las doce sesiones actualmente disponibles: tres por cada uno de los cuatro planes. Los días conceptuales que todavía no tienen contenido no se cuentan como progreso.

06

Validación, recuperación y migración

Antes de utilizar datos restaurados, la aplicación comprueba la versión del formato y valida cada registro. Los IDs inválidos o duplicados se descartan; los textos se normalizan y limitan; las categorías y estados desconocidos se sustituyen por valores seguros.

Las notas de seguimiento se conservan únicamente si tienen ID, texto y fecha técnica válidos. Los campos createdAt, updatedAt y answeredAt de las oraciones se normalizan cuando contienen fechas válidas.

Las reflexiones personales se limitan a 600 caracteres. Su createdAt y su updatedAt opcional se normalizan cuando son válidos. Una entrada antigua sin updatedAt sigue siendo compatible; la aplicación no inventa una fecha de edición.

Los estados anteriores de mimomento-local-v1 siguen siendo compatibles. Las fechas de actividad devocional deben corresponder a un formato válido YYYY-MM-DD, y las sesiones de plan se normalizan a una secuencia continua desde la sesión 1.

Si el JSON almacenado no puede leerse, la aplicación intenta recuperar registros personales válidos desde las claves heredadas devotionalPrayers y devotionalJournal. Si se encuentra una versión futura que esta demo no entiende, no se sobrescribe. Si el navegador bloquea localStorage, la demo continúa temporalmente en memoria.

07

Datos y contenido de demostración

La interfaz incluye oraciones y reflexiones precargadas para mostrar el diseño. Esos ejemplos se mantienen en el código y no se serializan en localStorage.

Las oraciones de ejemplo no pueden recibir notas, editarse, eliminarse ni cambiar de estado. Las reflexiones de ejemplo tampoco pueden editarse ni eliminarse como si fueran registros personales.

La biblioteca devocional también sigue siendo contenido de muestra. Cuando la persona marca el devocional diario o una de las tres sesiones disponibles de un plan como completada, esa acción sí se registra como progreso local real.

08

Seguridad y límites del almacenamiento local

localStorage mantiene los datos dentro del perfil del navegador, pero no constituye por sí mismo cifrado de extremo a extremo ni una bóveda protegida por contraseña. Una persona con acceso al mismo dispositivo, perfil del navegador o herramientas de desarrollo podría acceder a los datos del sitio.

Por tratarse de textos potencialmente íntimos, incluidas oraciones, notas de seguimiento y reflexiones del diario, se recomienda no utilizar la demo para información que requiera un nivel de protección superior al almacenamiento local del navegador.

09

Retención y eliminación

Las oraciones personales y las entradas personales del diario disponen de controles de eliminación dentro de la demo. Al eliminar una oración también se eliminan sus notas de seguimiento asociadas; al eliminar una reflexión, se retira ese registro de la colección local journal.

Los eventos de progreso devocional todavía no disponen de eliminación individual desde la interfaz. Permanecen en localStorage hasta que la aplicación incorpore esos controles o la persona borre los datos del sitio desde la configuración del navegador.

No existe una cuenta de usuario ni una base de datos remota de Mi Momento que requiera una solicitud separada de eliminación.

10

Servicios de terceros

La versión web se publica mediante GitHub Pages y utiliza recursos compartidos del ecosistema Neuronova Apps. No utiliza actualmente servicios publicitarios ni un SDK propio de analítica para las funciones principales descritas en esta política.

Los enlaces externos se rigen por las políticas del servicio de destino.

11

Funciones futuras y publicación móvil

Antes de incorporar cuentas, sincronización, copias de seguridad, recordatorios remotos, analítica, publicidad, SDK externos o una versión móvil distribuida mediante una tienda, se revisarán el tratamiento de datos, permisos, bibliotecas y declaraciones públicas aplicables.

Las declaraciones de seguridad de datos de cualquier tienda deberán corresponder al funcionamiento real de la versión publicada, no a funciones previstas.
